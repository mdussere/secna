# What three months of GitLab merge requests say — findings from the SECNA run

> Workline `secna_notebook`, Step 4 (run review). Written 2026-10-25 from the first full run of
> `notebook/test_secna.py`. **Kept as a working note — not integrated into the talk or the storyboard yet.**
> Public data only (GitLab.com public API); no contributor name or handle is quoted.

**Question it answers**: when the recipe runs on a real, large, public corpus, what does it let us see
— and what would we not see otherwise?

---

## 1. The corpus

- **Source**: every merge request (MR) **created between 2026-07-23 and 2026-10-23** in seven
  repositories that cover the GitLab environment: `gitlab-org/gitlab` (the product),
  `ops/artifact-registry`, `modelops/applied-ml/code-suggestions/ai-assist` (the AI assistant's
  backend), `orbit/knowledge-graph` (Orbit), `editor-extensions/gitlab-lsp` (language server, Duo CLI),
  `gitlab-runner`, `cli`.
- **Size**: **24,396 MRs**, 1,017 authors; merged 18,193 · closed without merge 3,795 · open 2,408.
  `gitlab-org/gitlab` alone holds 17,644.
- **Metadata kept** (one flat table, `corpus.parquet`): state, dates, author, reviewers, approvers,
  labels (and GitLab's scoped labels as columns: type, stage, group, section…), milestone, branches,
  size (lines, files, commits), comments.
- GitLab's own labels say **54 % maintenance, 25 % feature, 17 % bug**.

## 2. How the run was made

| Step | What | Choice | Cost |
|---|---|---|---|
| Extract | GitLab public GraphQL, 100 MRs per page | no account, ~20 min | free |
| **S** | one markdown text per MR: title · repository · origin · labels · description | no LLM; cut at 8,191 tokens (208 texts, 0.85 %) | free |
| **E** | `text-embedding-3-large`, batches of 32, resumable | 24.4 M tokens, 26 min | ≈ $3.17 |
| **C** | k-means on the raw vectors, **K = 100**, fixed seed | no reduction, 44 s | free |
| **N** | one call per cluster: a facts line (size, authors, origin shares, MRs per month) + the 10 MRs closest to the centre → name (8–15 words) + description (what, where, why, **how**) | `gpt-6-luna` | ≈ 1.3 M tokens, ≈ $0.17 |
| **A** | one call: every cluster (number, name, description) → **5 to 7 themes**, with a context line (*what the company does and how it operates*) | `gpt-6-luna`, high reasoning effort | ≈ 14 k tokens, < 1 cent |

**One run ≈ $3.35**, 95 % of it the embeddings (with `text-embedding-3-small`, ≈ $0.65 in all).
Counterfactual: a cheap model reading every MR ≈ $5; a strong model (`gpt-5.5`) ≈ $250 — and no
context window holds 24 M tokens.

**`origin`** (who made the MR) is derived in S from metadata and content: *bot* (GitLab's bot flag or
the `automation:bot-authored` label — the flag alone misses most bots), *agent* (an autonomous agent
account), *human + agent* (an agent signature in the description: *Generated with Claude Code*,
*AI-authored change*, *generated by GitLab Duo*…), else *human*. A further signal found afterwards —
branches named `duo/…`, created by the Duo Agent Platform under the person's account — is not yet in
the rule (see §6).

## 3. How I read the result

1. **Every cluster read**: the 100 names and descriptions, with size, origin shares, type and the
   month-by-month count (duckdb).
2. **Naming checked by sampling**: for 7 clusters, the 4 MRs nearest the centre, 4 at random, the 4
   farthest. Specific clusters are named well; broad ones get a name too narrow or vague; the far edge
   drifts (expected: names come from the 10 nearest MRs).
3. **Aggregation checked by re-running**: three runs of the same prompt gave 9 themes each time,
   pairwise agreement 0.94–0.97 — a stable core (AI agents, Artifact Registry, dependencies, docs,
   security, tests), ~20 border clusters that move.
4. **Metadata crossed with the clusters**: origin, branches, authors per cluster, merge rate, months.
   Most of the findings below come from this crossing, not from the names alone.

### My own reading: three movements at once

Read cluster by cluster, the corpus tells a story by **purpose** rather than by layer:

1. **Building the agent platform — and making it sellable** (≈ 22 % of MRs).
2. **Launching new products**: Artifact Registry (a whole product built in three months, now winding
   down: its main clusters fall from ~300 to ~110 MRs a month) and Orbit, the code knowledge graph
   (ramping up ×6, *Orbit GA* in the titles), with monetisation everywhere (trials, credits, quotas).
3. **Keeping a large, long-lived product running** (≈ 60 %): enterprise foundations (organisation
   tenancy, granular permissions, tokens, rate limits, audit), performance, large migrations (Vue 2 →
   3, Markdown API docs → OpenAPI), test engineering — and **≈ 10 % of all MRs that no human writes**
   (dependency bumps, version refreshes, migration finalisation, documentation syncs and AI
   translations).

The aggregation is where the point of view enters: asked neutrally, the model groups by layer; asked
*what the company does and how it operates*, the names gain the *how*, but the grouping still follows
the kind of work. The clusters are the solid material.

## 5. Seven signals — what we would not have seen otherwise

None of these is visible in a list of themes or in GitLab's labels. Each comes from crossing a
cluster with the metadata.

1. **GitLab builds Duo, but its engineers increasingly code with Claude Code.** MRs signed by Claude
   Code: **121 → 505 → 1,291** a month (239 authors, 377 of them in the AI theme itself); MRs from a
   `duo/` branch: **540 → 445 → 473**, flat. By October, signatures of the third-party tool outnumber
   in-house agent branches about 2.7 to 1. *Caveat: Claude Code signs by default; Duo leaves a trace
   through its branch and may be under-counted.*
2. **The *Fix Pipeline* agent: 219 attempts, 14 merged.** 219 MRs opened by the Duo *Fix Pipeline*
   agent for 114 people; **6 % merged**, 202 closed — 120 within a day. Either it is used as a
   diagnostic (read its fix, redo it by hand) or it is not yet good enough. A measure of an agent's
   real effectiveness that no product page gives.
3. **Agents will be paid by usage — "GitLab Credits".** Per-session credit ingestion for agent
   workflows, per-model credit rates, credits dashboards, caps and "credits exhausted" banners. The
   business model is moving to consumption, read straight from the code.
4. **Agents write for agents, humans correct them.** An automated agent account regularly updates
   *AI development principles from SSOT* — the development docs distilled into rules for the other
   agents (cluster 18, 77 % agent). Humans turn faulty agent sessions into instructions — *distill
   session traces into agent harness fixes* — 87 different people do it (cluster 27). Agent memory is
   being built (*user memory storage for Duo*). A learning loop around agents, in production.
5. **Govern every agent, not only your own.** AI governance sessions and audit are extended *so
   Claude Code and other agent activity can appear in governance reports* (cluster 87). With signal 1:
   if you cannot be the only agent, be the place where all agents are governed.
6. **Agents leave the IDE — Slack.** 130 MRs mention Slack: a `slack_assistant` flow, private
   Slack-originated sessions, one Duo group per Slack workspace.
7. **Proving ROI before selling.** The largest cluster of the AI theme (96, 334 MRs, 40 → 156 → 138)
   is not an agent capability but the **impact dashboard** that measures what agents bring (adoption,
   MR cycle time).

## 6. What we can and cannot tell about agents

| Signal | MRs | Reliability |
|---|---|---|
| Bot account or `automation:bot-authored` label | 2,365 (9.7 %) | high |
| Autonomous agent account | 135 (0.6 %) | high, few cases |
| Agent signature in the description | 2,174 (8.9 %) | high when present |
| `duo/…` branch (agent-made, person as author) | 1,559 (6.4 %) | high — **not yet in `origin`** |

- Visible agent involvement: **9.6 % with the current rule, 15.9 % with the branch signal**; the two
  signals hardly overlap (31 MRs).
- **Not visible**: unsigned agent use. Suspects are the one-author "campaigns" — e.g. 121 near-identical
  MRs in one month by a single author. 74.5 % "human, no trace" is a ceiling, not a measure.
- **Not authorship**: `GitLabDuo` as reviewer (83 % of MRs) is automatic review; the `automation:ml`
  label (1,538 MRs) is ML triage labelling.

## 7. Limits and open points

- Names come from the 10 MRs nearest the centre: biased to the core of each cluster.
- Two catch-all clusters (8, 65); one cluster of test MRs marked *do not merge* (59) — could be filtered
  in S.
- Theme borders move from run to run; the core does not.
- The signals are **questions to check**, not conclusions (signature-based counts; a possible
  diagnostic use of the Fix Pipeline agent; Artifact Registry's slowdown to check against public
  release notes).
- To do if kept: add the `duo/` branch signal to `origin`; re-letter themes by size.

**For the talk, in one sentence**: *on a donné 24 000 merge requests à une recette à 3 dollars, et on a
vu ce qu'aucun tableau de bord ne montre — un agent concurrent adopté plus vite que le sien, un agent
de réparation dont 94 % des tentatives sont abandonnées, un modèle économique qui bascule vers l'usage.
La recette fait émerger les questions ; elle ne les tranche pas.*
